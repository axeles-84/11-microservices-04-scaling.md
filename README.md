## ☸️ Задача 1: Кластеризация — Kubernetes

**Kubernetes** — оптимальный выбор для крупной компании с микросервисной архитектурой, так как это единственное решение, которое одновременно обеспечивает максимальную масштабируемость, богатейшую экосистему и полный набор встроенных примитивов для выполнения всех требований.

### Ключевые причины выбора:

* 🧩 **Соответствие всем требованиям «из коробки»:**
  * **Обнаружение сервисов и маршрутизация:** Kubernetes автоматически назначает DNS-имена и IP-адреса каждому сервису, обеспечивая балансировку нагрузки без изменения кода приложения.
  * **Горизонтальное масштабирование:** Достаточно изменить количество реплик в манифесте `Deployment`.
  * **Автоматическое масштабирование:** `Horizontal Pod Autoscaler (HPA)` автоматически изменяет количество подов на основе метрик CPU, памяти или кастомных метрик.
  * **Разделение ресурсов:** `Ingress` контролирует внешний доступ, а `Network Policies` изолируют трафик между сервисами внутри кластера.
  * **Конфигурация:** `ConfigMap` и `Secret` позволяют передавать переменные среды и чувствительные данные без пересборки образов.

* 🚀 **Превосходная масштабируемость.** 
  Kubernetes масштабируется до **5000+ узлов** и **150 000 подов** в одном кластере, что с запасом покрывает потребности крупной компании. Docker Swarm, например, практически ограничен ~1000 узлами.

* 🌍 **Богатейшая экосистема.** 
  Вокруг Kubernetes существует **1700+ проектов CNCF**, включая решения для CI/CD (`ArgoCD`, `Flux`), наблюдаемости (`Prometheus`, `Grafana`), service mesh (`Istio`, `Linkerd`) и управления секретами (`External Secrets`, `Vault`). Это позволяет построить полноценную платформу, не изобретая велосипед.

* 🔐 **Гибкость в управлении секретами.** 
  Хотя встроенные Kubernetes Secrets кодируются лишь в `base64` и не являются полностью безопасными, существует множество проверенных решений. Для крупной компании рекомендуется использовать **External Secrets Operator (ESO)** для синхронизации секретов из внешнего хранилища (например, **HashiCorp Vault**) в нативные Kubernetes Secrets. Это обеспечивает централизованное управление, аудит и ротацию ключей.
